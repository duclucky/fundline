# Spec: Workflow billing via non-custodial per-run escrow (Arc, USDC)

Status: DRAFT for build (2026-06-28). Charges users for AI workflow runs through a
non-custodial escrow on Arc. Build the contract via the `escrow-build` skill (escrow-engineer
writes, contract-auditor MUST verify the invariants, then wire + test). Nothing deployed.

Conventions: non-custodial (no owner/admin may withdraw user/escrowed funds beyond the rules
below), USDC 6 decimals (parseUnits(amount, 6); 0.05 USDC = 50000 base units), no fee, English,
no em dashes, no emojis, CommonJS / two-space / double quotes for any JS, minimal IERC20.

## Reference

Pattern adapted from Circle's official Arc escrow sample contract
`circlefin/arc-escrow` -> `contracts/escrow_smart_contract/RefundProtocol.sol` (non-custodial at
the contract level: funds move depositor -> contract -> beneficiary by rule; no admin drain; no
fee on the normal path; events on deposit/withdraw/refund). We REUSE that pattern and DROP its
app layer (Circle Developer-Controlled Wallets = custodial signing, OpenAI validation, Supabase).
In Fundline the END USER signs from their own EIP-1193 wallet; Fundline signs release/refund with
its treasury key. Related: `escrow-spec.md` is the broader milestone escrow; this is the narrow
per-run fixed-price billing case (build as its own minimal contract for audit simplicity).

## Model (decisions locked 2026-06-28)

- Per-run escrow: each workflow run is one escrow entry (keyed by runId). User pre-funds, so
  payment is guaranteed (solves "user spends the money before we can bill").
- User signs the deposit from their OWN wallet. On Run: check wallet USDC balance; if enough,
  user signs approve + fund for the workflow's FIXED price; if not, prompt to top up.
- Fixed price per workflow (profit kept, loss absorbed). No per-node cost charged.
- Output produced -> Fundline TREASURY signs release; the escrow pays the treasury and emits the
  memo. Workflows are first-party and deterministic, so output = release (no user confirm, no AI
  gate, no review window for release).
- Failure -> refund to the user (treasury-signed), PLUS a timeout so the user can self-refund if
  the treasury neither releases nor refunds (protects the user; keeps it non-custodial).
- Memo: FundlineEscrow self-emits it at release, in the SAME `InvoiceMemo` event format/topic as
  FundlineMemoRouter, reusing the memo-util builder (so the existing indexer/verify reads it).

## Contract: FundlineRunEscrow (non-custodial)

Constructor: `(address usdc, address treasury)` - both immutable. `treasury` is the fixed,
only beneficiary. No owner, no upgradeable proxy, no selfdestruct, no fee.

  struct Run {
    address payer;          // the user
    uint256 amount;         // fixed price, 6-dec USDC
    uint64  refundDeadline; // payer may self-refund after this if not released
    bool    released;
    bool    refunded;
  }
  mapping(bytes32 => Run) public runs;   // key = runId (server-generated bytes32)

Functions:
- `fund(bytes32 runId, uint256 amount)` - msg.sender = payer. `IERC20(usdc).transferFrom(payer,
  address(this), amount)`; require runs[runId].payer == 0 (unused id); store
  { payer, amount, refundDeadline = block.timestamp + REFUND_WINDOW }. emit `RunFunded(runId,
  payer, amount)`. Requires the user approved this contract for `amount` first.
- `release(bytes32 runId, bytes memo)` - onlyTreasury. require funded, not released, not refunded.
  set released; `IERC20(usdc).transfer(treasury, amount)`. emit
  `InvoiceMemo(runId, payer, memo)` (same sig/topic as the memo router) + `RunReleased(runId,
  payer, amount)`.
- `refund(bytes32 runId)` - onlyTreasury. require funded, not released, not refunded. set
  refunded; `transfer(payer, amount)`. emit `RunRefunded(runId, payer, amount)`.
- `claimRefund(bytes32 runId)` - msg.sender = payer, only after refundDeadline, not released, not
  refunded. set refunded; `transfer(payer, amount)`. emit `RunRefunded(...)`. (User safety net.)
- `getRun(bytes32 runId) view`.

Use SafeERC20 or check transfer/transferFrom return values (the Circle sample uses unchecked
transfers; we harden). REFUND_WINDOW: a few hours (config constant), long enough to run, short
enough that a stuck run frees the user.

### Invariants the contract-auditor MUST verify
- Funds only move: payer -> escrow (fund); escrow -> treasury (release); escrow -> payer (refund
  / claimRefund). No other transfer path. No function lets treasury or anyone redirect to an
  arbitrary address or take more than runs[runId].amount.
- treasury can ONLY release-to-treasury or refund-to-payer; cannot touch a run's funds in any
  other way; cannot withdraw a different run's surplus.
- No fee, no owner-drain, no selfdestruct, no proxy/upgrade.
- A funded run is always terminally either released XOR refunded; no double-release / double-refund
  / re-fund of an existing runId.
- 6-decimal USDC; no 18-decimal assumption.

### Trust boundary (document honestly)
release is treasury-gated and cannot be proven on-chain to correspond to real output. The user
accepts this for a first-party fixed-price service. The contract still bounds treasury power to
"release the exact funded amount to the treasury, or refund to the payer," and the refund timeout
gives the user recourse if the treasury goes silent. It does NOT protect against a treasury that
releases without delivering output (off-chain trust, same as any prepaid service).

## Memo content (professional, InvoiceMemo format)

Reuse the memo-util builder (add `buildWorkflowMemoText`). Plain UTF-8, well under 2048 bytes.
Contains: workflow name + the nodes used with their model. NO per-node cost, NO user name, NO
input/output. Example:

  Fundline workflow receipt
  Workflow: Client Research
  Steps:
   1. Role analysis - gpt-4o-mini
   2. Research plan - gpt-4o-mini
   3. Web research - Tavily
   4. Report writer - gpt-4.1-mini

## Server + frontend integration

- New env: `ARC_RUN_ESCROW_ADDRESS` (the deployed contract). `GET /api/config` returns
  `runEscrowAddress` + the fixed workflow price, alongside the existing router/usdc fields.
- `POST /api/workflows/:slug/run` (existing) gains a billing path when billing is enabled:
  1. Server returns a runId + the fixed price + escrow address so the client funds it.
  2. Client (app.js style, hand-rolled Arc tx via EIP-1193): approve USDC -> `fund(runId, price)`;
     wait for the fund tx; then call /run with the runId.
  3. Server verifies the run is funded on-chain (read `getRun(runId)`, payer = caller, amount =
     price, not released/refunded) BEFORE executing the workflow. Guard against reusing a runId.
  4. Run the chain (v98store). On success: treasury signs `release(runId, memo)` with the
     workflow memo. On failure: treasury signs `refund(runId)` (or let the timeout handle it).
  5. Return output + the release tx hash.
- Keep the per-IP / global rate-limit caps too (defense in depth); billing replaces "free beta".
- Treasury key: a Fundline-controlled hot key (NOT a user key, so non-custodial holds) in the
  cPanel env, e.g. `ARC_TREASURY_PRIVATE_KEY`; sign release/refund server-side. Secret, never
  client-side, never committed.

## Pricing

Fixed USDC price per workflow, quoted up-front from `/api/config`. The real v98 cost is internal
(profit/loss is ours). Set per-workflow (e.g. client-research 0.05 USDC = 50000 units).

## Build order (via escrow-build)

1. escrow-engineer writes contracts/FundlineRunEscrow.sol + deploy script (mirror
   scripts/deploy-payment-router.js, solc, write ARC_RUN_ESCROW_ADDRESS to .env).
2. contract-auditor verifies every invariant above. Do NOT proceed on a fail.
3. Wire /api/config + the /run billing path + memo-util buildWorkflowMemoText + a treasury signer.
4. Tests: fund/release/refund/claimRefund lifecycle, double-spend / re-fund guards, 6-decimal
   math, memo format, refund-after-timeout, and that release/refund are treasury-only.
5. predeploy-check, then deploy the contract (testnet first) + set cPanel env (escrow address,
   treasury key, enable billing) + restart.
